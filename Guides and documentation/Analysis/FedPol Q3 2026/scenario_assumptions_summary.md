# Federal Policy Scenario Assumptions Summary

Comparison of the four core `s4x1_fedpol_*` scenarios: `fedpol_biden`, `fedpol_current`, `fedpol_reinstate`, `fedpol_cost_optimal`. Values are drawn from `pg/extra_inputs/scenario_inputs.csv` and `pg/settings/scenario_management.yml`.

| Category | `fedpol_biden` | `fedpol_current` | `fedpol_reinstate` | `fedpol_cost_optimal` |
|---|---|---|---|---|
| **Framing** | Biden-era policy continuation | Current federal policy (rollback) | Current policy, credits later reinstated | Unconstrained cost-optimal by 2035 |
| **Federal tax credits** (`tax_credits`) | `full_ira` — full IRA wind/solar credits, all periods | `no_wind_solar` — credits repealed for wind/solar, all periods | `no_wind_solar` 2024–2028 → `full_ira` from 2030 | `no_wind_solar` — no subsidy in any period (pure cost competition) |
| **EPA power-plant CO2 rule** (`clean_power_regs`) | `caa_2024_rule` — 2024 Clean Air Act rule in effect | `none` — repealed | `none` — repealed | `none` — repealed |
| **Coal/gas retirement policy** (`retirement_policy`) | `baseline` — normal economic retirement | `blocked_2030_coal_gas` — coal/gas retirements forced to stay online through 2029 | `blocked_2030_coal_gas` — same forced retention | `baseline` — normal economic retirement |
| **Offshore wind policy** (`offshore_wind_policy`) | `open` — no restriction | `capped_2025` — state offshore mandates zeroed/capped | `capped_2025` — same cap | `open` — no restriction |

## Notes

- **`current` and `reinstate` are identical** in every column except `tax_credits` (reinstate flips to `full_ira` from 2030) and `gen_zone_ratio` (reinstate adds the state pacing constraint) — everything else (retirements blocked, offshore capped, tariffs, high gas) is shared.
- **`biden` and `cost_optimal` share the "permissive" policy backdrop** (baseline retirement, open offshore, no tariffs, standard gas prices) but diverge sharply on the *economic* drivers: `biden` gets there via subsidy (`full_ira`) with caps still binding; `cost_optimal` gets there via unsubsidized cost-competition with caps deliberately phased out and transmission unconstrained.
- Columns identical across all four and omitted from the table above: `time_series`, `allow_retirement`, `rggi`, `transmission`, `hurdle`, `degrade`, `asymmetry`, `build_minimum`, `ccs_capture_rate`, `resource_limits`, `barrier_reduction`.

## Known issue: `cost_optimal`'s national wind/solar cap release doesn't work (as of 2026-07-20, unresolved)

`constraint_removal: partial`/`full` is designed to release the **national** `MaxCapTag_WindGrowth`/`MaxCapTag_SolarGrowth` caps at 2030/2035 (in addition to the 9 regional `MaxCapTag_WindGrowth_<transreg>` sub-caps, which `full` already releases correctly). Both possible implementation approaches are structurally blocked:

1. **`model_tag_values` (zero out the tag)** — the currently-configured approach. Doesn't work because `max_cap_generators.csv` (which pg_to_switch.py derives generator↔tag membership into) has no `PERIOD` column; membership is necessarily static across a whole foresight case. `gen_info_file()` collapses the multi-period generator dataframe to one row per generator before deriving this file, so whichever period's tag assignment comes first silently applies to every period. Confirmed via a dry `pg_to_switch.py` build for `s4x1_fedpol_cost_optimal`: the same wind generators stayed tagged under `MaxCapTag_WindGrowth` identically at 2028/2030/2035.
2. **`MaxCapReq` (raise the ceiling)** — tried as a fix, then reverted. This works correctly for the regional sub-caps (period-aware via `cap_req_files()`, and no other axis touches those keys), but for the *national* tags it's a dead end: the `policies` axis (`policies: current`, used by all four fedpol scenarios) already sets its own genuinely period-varying `MaxCapReq.MaxCapTag_WindGrowth`/`MaxCapTag_SolarGrowth` values every year (a growing "National Wind/Solar Growth Limit" target — confirmed 209,901→238,881→311,331 MW across 2028/2030/2035 for wind). `constraint_removal` lives under `all_years` in `scenario_management.yml`, applied *before* the year-specific `policies` block in PowerGenome's merge order (`build_scenario_settings()` in `PowerGenome/powergenome/util.py`), so `policies` always silently overwrites it — confirmed by directly inspecting the merged settings dict. Moving the override into a year-specific block instead isn't a workaround either: PowerGenome hard-crashes (`ValueError`) if two different `scenario_inputs.csv` columns touch the same settings leaf within the same year-pass, and `policies` has an unavoidable claim on these two keys for every year.

**Net effect:** for any case using a *single* `constraint_removal` value for its whole horizon, `model_tag_values` works fine (there's only one answer, so the per-period collapse doesn't matter). But `s4x1_fedpol_cost_optimal`'s intended `none@2028 → partial@2030 → full@2035` schedule genuinely cannot express "release the national cap starting only at 2030" with either mechanism as currently designed. A real fix needs either a `PERIOD` column added to `max_cap_generators.csv` (+ a matching change in `switch/study_modules/max_capacity_constraint.py` to filter membership by period) or some other way to resolve the `policies`/`constraint_removal` collision. Not yet fixed — flagging for a decision on how to prioritize this before running `cost_optimal` for real.
