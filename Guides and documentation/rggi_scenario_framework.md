# RGGI Scenario Framework

**Branch:** `tom/carbon-caps`  
**Completed:** 2026-05-12  
**Resolves:** I-15, I-16, I-18 (from P-09)

---

## Overview

The RGGI scenario framework implements a 16-scenario run matrix per model year (2028, 2030, 2035) for RGGI carbon policy sensitivity analysis. It uses a hybrid approach: separate input folders per load case, `--input-alias` flags at solve time for policy/RGGI/fossil fleet variants.

Total runs: 3 years × 2 load cases × 8 policy variants = 48 solves.

---

## Run Matrix

Each year has 16 runs across two load cases and eight policy variants:

| Variant | NSP | VA | HF |
|---------|-----|----|----|
| baseline | — | — | — |
| nsp | ✓ | — | — |
| va | — | ✓ | — |
| hf | — | — | ✓ |
| nsp_va | ✓ | ✓ | — |
| nsp_hf | ✓ | — | ✓ |
| va_hf | — | ✓ | ✓ |
| nsp_va_hf | ✓ | ✓ | ✓ |

**Dimensions:**
- **NSP (No State Policy):** replaces `rps_requirements.csv`, `rps_generators.csv`, `min_cap_requirements.csv`, `min_cap_generators.csv` with blank header-only equivalents via `--input-alias`
- **VA (Virginia RGGI):** replaces `carbon_policies_regional.csv` with `carbon_policies_regional_va.csv`, which adds ~2 Mt of VA allowance budget (expanding ETS 1 cap from 12.52 to 14.49 Mt in 2035)
- **HF (High Fossil):** replaces `gen_info.csv` with `gen_info.high_fossil.csv` (no retirement + $80/MWh penalty on new clean tech), generated by `define_scenarios.py`

**Load cases:**
- `s4x1_edf_med`: EDF/EPRI medium load growth scenario
- `s4x1_icf`: ICF higher load growth (data center and EV-driven)

## Alias File Generation

Alias files are generated automatically by `pg_to_switch.py` alongside standard input files. No separate pg_to_switch runs are needed per variant.

### NSP alias files

For every input folder, `pg_to_switch.py` writes header-only (zero-row) versions of the four policy files:
- `rps_requirements_nsp.csv`
- `rps_generators_nsp.csv`
- `min_cap_requirements_nsp.csv`
- `min_cap_generators_nsp.csv`

### VA alias file

For cases with `rggi: RGGI10` in `scenario_inputs.csv`, `pg_to_switch.py` generates `carbon_policies_regional_va.csv` alongside the standard file. The VA budget is sized as:

```
VA cap per zone = total_10state_cap × (va_fraction / (1 - va_fraction)) / n_zones
```

where `va_fraction = 0.25` and `n_zones = 4` (p99, p100, p118, p124). This adds VA's proportional share relative to the 10-state program without changing any existing state's budget.

The 25% figure is a conservative assumption for VA rejoining: VA's historical share of RGGI-11 total emissions is slightly above 25%, so this slightly understates the cap expansion. The resulting gross-up factor is 4/3 (i.e. total RGGI-11 cap = 10-state cap × 4/3).

Settings controlling VA alias generation (under `RGGI10` entry in `scenario_management.yml`):
```yaml
rggi:
  RGGI10:
    rggi_va_alias_fraction: 0.25
    rggi_va_alias_zones: [p99, p100, p118, p124]
```

## CCR Implementation

The RGGI Cost Containment Reserve (CCR) is implemented as two additional CO₂ programs (`ETS 1_CCR1`, `ETS 1_CCR2`) with a hard pool cap:

| Tier | Pool | 2028 price | 2030 price | 2035 price |
|------|------|-----------|-----------|-----------|
| CCR Tier 1 | 10.66 Mt/yr | $23.00/tCO₂ | $26.34/tCO₂ | $36.93/tCO₂ |
| CCR Tier 2 | 10.66 Mt/yr | $34.50/tCO₂ | $39.50/tCO₂ | $55.39/tCO₂ |

Prices escalate at 7%/yr from a 2027 base of $19.50 (T1) and $29.25 (T2) per short ton, converted to $/metric tonne (÷0.907185).

CCR trigger prices are set per year in `scenario_management.yml` under `{year}: policies: current: carbon_ccr_prices`.

### CCR price mechanics

The CCR creates a step-function allowance supply curve:
1. Base cap allowances at $0 (up to the cap)
2. CCR Tier 1 allowances at exactly T1 price (up to 10.66 Mt)
3. CCR Tier 2 allowances at exactly T2 price (up to 10.66 Mt)
4. Above both pools: infeasible

When T1 is drawn but not exhausted, the LP clearing price is exactly T1 trigger price (the CCR pool is perfectly elastic at that price). Prices between T1 and T2 do not occur — the CCR pools are discrete tiers, not a continuous supply curve.

### CCR pool sizes in VA scenarios

The CCR pools are defined in `carbon_policies_ccr.csv` (separate from `carbon_policies_regional.csv`) and are **not** affected by the `--input-alias carbon_policies_regional.csv=carbon_policies_regional_va.csv` flag used in VA variants. As a result, CCR pool sizes remain at the 10-state values (10,656,120 tCO₂/yr per tier) even when VA rejoining is modelled.

This is a further conservative assumption: under a true RGGI-11 program, CCR pools would be proportionally scaled upward alongside the expanded cap (by a factor of ~4/3). Keeping them at 10-state levels understates the CCR cushion available to a VA-inclusive program.

## Clearing Price Output

`carbon_policies_regional.py` writes `carbon_program_clearing_prices.csv` to each output folder after every solve. Columns:

| Column | Description |
|--------|-------------|
| `CO2_PROGRAM` | Program name (ETS 1, ETS 1_CCR1, etc.) |
| `PERIOD` | Model year |
| `cap_tco2_per_yr` | Total allowance budget |
| `emissions_tco2_per_yr` | Actual emissions |
| `surplus_tco2_per_yr` | cap − emissions |
| `violation_tco2_per_yr` | CCR allowances purchased |
| `clearing_price_dollar_per_tco2` | LP dual (shadow price) |
| `ccr_tier1_purchases_tco2` | T1 CCR draws |
| `ccr_tier2_purchases_tco2` | T2 CCR draws |

### Solver requirement: crossover=1

The Gurobi barrier solver (`crossover=0`) produces unreliable LP duals when the cap binds with no CCR purchases — the reported price anchors to the nearest CCR trigger value rather than the true shadow price. Always use `crossover=1`:

```
switch solve ... --solver-options-string "crossover=1"
```

This is enforced in `run_rggi_solves.py`. Do not run RGGI scenarios without it.

## p18-p19 Transmission Fix

The NARIS 2024 dataset is missing the 18-19 transmission line. This is corrected automatically for every input folder by `adjust/fix_p18p19_transmission.py` (registered at order 12 in `pg/settings/switch.yml`). The fix is idempotent — it re-inserts the line only if absent.

## Running the Matrix

```bash
cd switch
conda run -n switch-pg-reeds python run_rggi_solves.py
```

By default runs all three years (2028, 2030, 2035). To run specific years:

```bash
conda run -n switch-pg-reeds python run_rggi_solves.py 2035
conda run -n switch-pg-reeds python run_rggi_solves.py 2028 2030
```

Outputs are written to `switch/out/RGGI/{year}/{case}/{variant}/`.
