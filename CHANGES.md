# Transmission Modeling Changes

This document records all changes made to add asymmetric transmission, new-build
capacity derating, and hurdle costs to the ReEDS/Switch/PowerGenome pipeline.

---

## 1. Bug Fix — `external_data.py`

**File:** `PowerGenome/powergenome/external_data.py` (line 618)

**Problem:** `Line_Min_Flow_MW` was being assigned from `Line_Max_Flow_MW` (always
positive), destroying directional capacity information for lines with asymmetric
flow limits.

**Fix:**
```python
# Before (bug):
tx_df["Line_Min_Flow_MW"] = tx_df["Line_Max_Flow_MW"].fillna(0)

# After (fix):
tx_df["Line_Min_Flow_MW"] = tx_df["Line_Min_Flow_MW"].fillna(0)
```

## 2. New Switch Module — Hurdle Costs

**File (new):** `switch/study_modules/trans_hurdle_cost.py`

Adds a per-MWh operational cost to all power flows crossing hurdle-region boundaries.
Cost rates are read from `trans_hurdle_cost.csv` (generated by `pg_to_switch.py`) and
added to the objective function via `Cost_Components_Per_TP`. The cost applies
symmetrically to flows in both directions on each cross-boundary line.

**Input file produced:** `switch/in/<year>/<case>/trans_hurdle_cost.csv`
- Columns: `TRANSMISSION_LINE, PERIOD, trans_hurdle_cost_per_mwh`
- Sourced from `cost_hurdle_intra.csv` (hurdlereg column), matched to the closest
  available year for each model period.

---

## 3. New Switch Module — New-Build Capacity Derating

**File (new):** `switch/study_modules/trans_new_build_derate.py`

Applies a 15% derating factor (0.85) to new transmission capacity built across
planning subregion (`transgrp`) boundaries. Replaces the core
`Maximum_DispatchTx` constraint with a new `Maximum_DispatchTx_Derated` constraint
that uses:

```
DispatchTx ≤ existing_cap × derating_factor + new_cap × new_build_derate_factor
```

Within-subregion new builds use the default factor of 1.0 (no derating).

**Input file produced:** `switch/in/<year>/<case>/trans_new_build_derate.csv`
- Columns: `TRANSMISSION_LINE, trans_new_build_derate_factor`
- Only lines crossing a `transgrp` boundary are written (factor = 0.85).

**Note:** This module deactivates `Maximum_DispatchTx` from the core dispatch module
and replaces it. It must load after `switch_model.transmission.transport.dispatch`.

---

## 4. New Switch Module — Asymmetric Directional Capacity

**File (new):** `switch/study_modules/trans_asymmetric_capacity.py`

Adds supplementary per-direction capacity constraints on top of the symmetric
`Maximum_DispatchTx` constraint. The tighter of the two limits applies; for lines
not in the input file, this module has no effect.

The constraints represent existing infrastructure limits from the NARIS2024 dataset.
New transmission built via `BuildTx` increases the symmetric nameplate capacity
tracked by the core model; the directional constraint applies to total dispatch, so
new builds may relax asymmetric limits if built on an asymmetric corridor.

**Input file produced:** `switch/in/<year>/<case>/trans_directional_limits.csv`
- Columns: `zone_from, zone_to, PERIOD, trans_directional_cap_mw`
- One row per direction per period for each line that has an entry in the NARIS2024
  source files.

## 5. `modules.txt` — New Module Registrations

**File:** `switch/modules.txt`

Three new modules added after `switch_model.transmission.transport.dispatch`:

```
study_modules.trans_new_build_derate
study_modules.trans_hurdle_cost
study_modules.trans_asymmetric_capacity
```

Load order is important: `trans_new_build_derate` must follow the core dispatch
module because it deactivates `Maximum_DispatchTx` via `BuildAction`.

## 6. `pg_to_switch.py` — Three New Data-Generation Blocks

**File:** `pg_to_switch.py`

Three blocks were added inside the per-scenario loop to generate the new input CSV
files. Each block is gated by a scenario-level policy flag (see §8).

### 6a. Derate block (inside hierarchy loop)
Iterates all transmission lines; for any line where `transgrp[lz1] != transgrp[lz2]`,
appends a row with `trans_new_build_derate_factor = 0.85` to `trans_new_build_derate.csv`.

### 6b. Hurdle-cost block (inside hierarchy loop)
Reads `cost_hurdle_intra.csv`, selects the closest available year to each model
period, and appends rows for all cross-`hurdlereg` lines to `trans_hurdle_cost.csv`.

### 6c. Asymmetric-capacity block (outside hierarchy loop)
Reads `transmission_capacity_init_AC_ba_NARIS2024.csv` (directional `MW_f0`/`MW_r0`)
and `transmission_capacity_init_nonAC_ba.csv` (symmetric DC/B2B MW). Builds a lookup
by zone-pair and appends two rows (one per direction) per line per period to
`trans_directional_limits.csv`.

**Supporting lookups added to hierarchy block:**
```python
zone_transgrp  = dict(zip(hierarchy["ba"], hierarchy["transgrp"]))
zone_hurdlereg = dict(zip(hierarchy["ba"], hierarchy["hurdlereg"]))
```

## 7. REFS2009 → NARIS Migration

### 7a. `pg/settings/extra_inputs.yml`
Changed the transmission constraints source from REFS2009 to NARIS:

| Setting | Old value | New value |
|---|---|---|
| `user_transmission_costs` | `network_costs_ReEDS_patched_for_REFS2009.csv` | `network_costs_ReEDS.csv` |
| `user_transmission_constraints_fn` | `reeds_ba_tx_REFS2009_avg.csv` | `reeds_ba_tx_NARIS_avg.csv` |

### 7b. `patch_pg_resource_groups.py`
The last section (lines 291–323) was replaced to regenerate
`pg/extra_inputs/reeds_ba_tx_NARIS_avg.csv` from local source files instead of
downloading REFS2009 from GitHub:

- AC lines: averages `(MW_f0 + MW_r0) / 2` from
  `transmission_capacity_init_AC_ba_NARIS2024.csv` (292 corridors)
- DC/B2B lines: taken directly from `transmission_capacity_init_nonAC_ba.csv`
  (10 lines)
- Output: 302 rows with columns `region_from, region_to, firm_ttc_mw, notes`

**Known gap:** 8 corridors present in REFS2009 are absent from the NARIS2024 dataset:
`p10-p12, p13-p25, p15-p21, p15-p25, p16-p18, p41-p70, p55-p85, p128-p132`.
These are silently excluded from newly generated cases. None of the affected zones
are fully isolated (each has other connections), but the capacity on these corridors
is lost. Consider adding them back to `reeds_ba_tx_NARIS_avg.csv` manually if needed.

## 8. Scenario Toggle Columns

### 8a. `pg/extra_inputs/scenario_inputs.csv`
Three new columns appended, defaulting to `yes` for all existing rows:

| Column | Values | Controls |
|---|---|---|
| `hurdle` | `yes` / `no` | Whether hurdle-cost data is written |
| `degrade` | `yes` / `no` | Whether new-build derate data is written |
| `asymmetry` | `yes` / `no` | Whether directional capacity data is written |

### 8b. `pg/settings/scenario_management.yml`
Three new mapping blocks added after the `trans_expansion` block:

```yaml
hurdle:
  yes:
    hurdle_policy: yes
  no:
    hurdle_policy: no
degrade:
  yes:
    degrade_policy: yes
  no:
    degrade_policy: no
asymmetry:
  yes:
    asymmetry_policy: yes
  no:
    asymmetry_policy: no
```

### 8c. Policy gates in `pg_to_switch.py`
Each feature block is conditioned on its policy setting (default `yes`):

```python
if settings.get("degrade_policy",  "yes") == "yes": ...
if settings.get("hurdle_policy",   "yes") == "yes": ...
if settings.get("asymmetry_policy","yes") == "yes": ...
```

When `asymmetry_policy` is `no`, both NARIS source file paths are set to `None` so
the block is skipped entirely without touching the filesystem.
